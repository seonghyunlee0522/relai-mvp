# UI/UX 전면 개편 요약

기존 기능·API·데이터 구조는 유지하고 정보 구조, 화면 공간, 입력 방식, 대량 데이터 처리 방식을 개선했다.

## 구조
- **Project Workspace**: 프로젝트 안의 모든 화면은 전역 LNB를 접어 두고(☰로 오버레이 표시) 상단 고정 헤더(☰ · 프로젝트명 · 현재 단계 · 진행률 · 등록자 · 상태 · KPI · 정보 수정)와 탭(Overview · 프로세스 · Requirements · WBS · Changes · Issues & Risks · Tests)을 쓴다. 프로젝트 목록·설정·새 프로젝트는 아이콘 레일로 접을 수 있는 LNB를 쓴다(`shell.js`, `project/guide.js`).
- **Data Grid** (`shared/grid.js`): 정렬 · 컬럼 표시/숨김 · 컬럼 폭 조절 · 페이지(50/100/200/500) · 다중 선택(Shift 범위, 필터 결과 전체 선택) · 인라인 편집(상태/범위/우선순위/유형/담당자/날짜/진행률) · 키보드 이동. 컬럼 설정은 localStorage에 저장된다. 요구사항 목록·Traceability, WBS(트리), 프로젝트 목록에 적용.
- **일괄 작업** (`shared/bulk.js`): 항목 + 값 + [일괄 변경]을 명시적으로 지정(실수 방지), 20건 이상은 확인, 500건 단위로 나눠 호출, 제외 건수·사유를 결과로 표시. WBS는 일정 이동(±일) 포함.
- **상세 보기**: 우측 Drawer 대신 큰 모달(탭: 업무정보 · 연결·검증/관계 · 댓글·활동, 이전/다음 이동). 변경 요청·Issue/Risk·테스트의 기존 Drawer도 CSS로 같은 모달 패턴으로 통일했다.
- **활동** (`shared/detail.js`): 댓글 + 변경 이력(상태·담당자·일정·수정·연결·시스템)을 시간순으로 합쳐 필터(전체/댓글/변경 이력)와 함께 표시. 항상 보이지 않고 탭에서만 연다.
- **Excel 가져오기** (`shared/importer.js`): 템플릿 내려받기 → 업로드 → 서버 검증 → 셀 단위 오류 표시·수정 → 다시 검증 → 가져오기(부분 성공) → 결과(총/성공/오류) + 오류 행 Excel 재다운로드. 요구사항·WBS(WBS Code 1, 1.1, 1.2.1 계층). 내보내기도 제공.
- **대시보드** (`project/overview.js`): KPI(진행률 · 전체 Task · 지연 Task · 미처리 요구사항 · 주요 이슈), 타임라인, 마일스톤, 7일 일정, 지연 Task, 담당자별 업무량, 최근 변경, 확인 필요, 프로젝트 상태, 주간보고, 현재 단계 가이드.
- **밀도**: 13.5px 본문, 32px 컨트롤, 34px 행, 6px 반경, 얕은 그림자. 기본 폭은 1440~1920 데스크톱 기준이고 모바일은 읽기 가능한 수준만 보장한다.

## 입력 방식 기준
단순 수정은 목록의 인라인 편집, 연속 입력은 빠른 추가 줄(Enter)과 "저장 후 계속 추가", 일반 입력·상세는 모달, 대량 입력은 Excel Import 마법사.

## 알려진 한계
- 산출물(파일) 엔티티가 데이터 모델에 없어 "산출물" 탭은 만들지 않았다. 대신 요구사항 상세에 연결·검증(WBS · 테스트 · 검수 · 이슈) 탭을 둔다.
- 프로젝트 PM 필드가 없어 헤더의 담당 표기는 프로젝트 등록자다.
- WBS 템플릿에는 우선순위·비고 열이 없다(WBS에 해당 필드가 없음).
- 변경/이슈/테스트 목록은 기존 테이블에 밀도·모달 스타일만 적용했고 인라인 편집·일괄 작업은 아직 없다.
